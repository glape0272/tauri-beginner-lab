# TypeScript基本から中級課題

この課題集は、画面側の処理を自分で組み立てるための課題です。

HTML、DOM、イベント、非同期処理、配列描画を分けて確認し、Tauri commandとの接続へ進みます。

## 進め方

- 先に画面で必要な状態を決める
- DOM取得、イベント登録、描画関数を分けて書く
- `null`の可能性を確認してから要素を使う
- Rust command呼び出しは`try/catch`で囲む

## 基本課題

### TS-01: DOM要素を取得する

対象ファイル:

- `index.html`
- `src/main.ts`

要件:

- テキスト入力、ボタン、表示領域を用意
- TypeScriptでそれぞれを取得
- 取得できない場合は処理を止める

制約:

- `querySelector`に型を付ける
- `as`による強制キャストは避ける

完了条件:

- 取得した要素の役割を説明できる

### TS-02: イベントで表示を変える

対象ファイル:

- `index.html`
- `src/main.ts`

要件:

- ボタン押下で入力値を表示領域へ出す
- 空文字の場合は既定文言を表示
- 表示文は関数で作る

制約:

- イベント登録は`DOMContentLoaded`後
- DOM更新処理を1つの関数に分ける

完了条件:

- 入力あり、入力なしで表示が変わる

### TS-03: typeでデータの形を決める

対象ファイル:

- `src/main.ts`

要件:

- 学習ログを表す`type`を作成
- id、タイトル、本文、完了状態を持たせる
- 仮データを2件作る

制約:

- 完了状態は`boolean`
- 日付を入れる場合は文字列で扱う

完了条件:

- どのフィールドが画面表示に必要か説明できる

## 中級課題

### TS-04: 配列を描画する

対象ファイル:

- `index.html`
- `src/main.ts`
- `src/styles.css`

要件:

- 学習ログ配列をHTMLへ描画
- 完了済みと未完了で見た目を変える
- 空配列の場合は空状態メッセージを表示

制約:

- 描画処理は`render`から始まる関数名
- `innerHTML`を使う場合、表示内容の出どころを説明できること

完了条件:

- 2件以上のログが一覧表示される
- 空配列時の表示がある

### TS-05: Rust commandをtry/catchで呼ぶ

対象ファイル:

- `src/main.ts`

要件:

- Rust commandを呼び、成功時と失敗時の表示を分ける
- 実行中の状態を画面に表示
- 失敗時はユーザー向けのエラー文を表示

制約:

- `await invoke<型>()`を使う
- `catch`内で`String(error)`を使って表示する

完了条件:

- 成功、失敗、実行中の3状態を説明できる

### TS-06: フォーム入力をオブジェクトにまとめる

対象ファイル:

- `index.html`
- `src/main.ts`

要件:

- タイトル、本文、学習時間の入力欄を作る
- 入力値を1つのオブジェクトにまとめる
- Rust commandへ渡せる形にする

制約:

- 数値入力は`Number()`で変換
- 入力取得と送信処理を分ける

完了条件:

- TypeScript側のオブジェクトとRust側の引数の対応を説明できる

## 仕上げ課題

### TS-07: 小さな状態管理を作る

対象ファイル:

- `src/main.ts`

要件:

- 学習ログ配列を状態として持つ
- 追加、完了切り替え、一覧再描画を実装
- 画面操作ごとに状態と表示を同期する

制約:

- グローバルな配列は1つまで
- DOM更新は描画関数に集約する

完了条件:

- 追加後に一覧が更新される
- 完了切り替え後に見た目が変わる
- 状態と表示の関係を説明できる
